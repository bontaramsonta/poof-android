# Control plane hosting limits

Research for [#3](https://github.com/bontaramsonta/poof-android/issues/3). Map: [#1](https://github.com/bontaramsonta/poof-android/issues/1).
Facts only. No decision is made here.

Sources checked 2026-10-04. Prices are us-east-1 list prices from the AWS Price List API (`pricing:GetProducts`).

## Question

Where can the thin control plane run on AWS, given an Exit takes ~60–90 s from `RunInstances` to first answering handshake?

1. Lambda function URL vs API Gateway HTTP API: request timeouts, bearer-token auth hooks, HTTPS defaults, cost at near-zero traffic.
2. Go on Lambda (`provided.al2023`, arm64) cold start.
3. Can one Lambda in one home region call EC2 in ~30 other regions?
4. Does the ~60–90 s wait force an async launch-then-poll API?

## 1. What poof's existing launch actually waits on

Source: `~/p/poof/internal/provision/aws.go`, `~/p/poof/internal/session/session.go`.

`Provisioner.Launch` makes these calls, all against one regional EC2/SSM client:

1. `ssm:GetParameter` — resolve the AL2023 arm64 AMI.
2. `ec2:CreateSecurityGroup` + `ec2:AuthorizeSecurityGroupIngress` (UDP 51820).
3. `ec2:RunInstances` (t4g.nano, user-data, `poof=1` tag, shutdown behaviour = terminate).
4. `ec2:DescribeInstances` every 2 s until `PublicIpAddress` is set.

`Launch` returns as soon as the instance has a public IP. Its doc comment says it does **not** wait for the tunnel. The ~60–90 s cloud-init wait is the *client's* `WaitForHandshake`, run against the returned IP with a 3-minute timeout (`session.go`, `hsCtx ... 3*time.Minute`).

Consequences for the control plane, stated as facts about the current code:

- The work the control plane would do on the phone's behalf ends at "public IP known". The handshake wait happens on the device that holds the WireGuard client key.
- WireGuard keypairs are generated by the caller (`session.Provision`). The server private key goes into user-data; the client public key is the only accepted peer.
- No AWS doc gives a latency bound for `RunInstances` → public IP. The code polls with no fixed upper bound other than the caller's context. This duration was not measured for this note.
- `countryToRegion` (`regions.go`) currently has **12** Countries, all in regions enabled by default (none are opt-in regions). The ~30-region figure in the ticket is a target, not the current code.

## 2. Lambda function URL vs API Gateway HTTP API

| | Lambda function URL | API Gateway HTTP API |
|---|---|---|
| Max request duration | Lambda function timeout: default 3 s, max **900 s** (15 min) [L-timeout] | **30 s** maximum integration timeout, **not** increasable [AG-quotas] |
| Auth options | `AuthType` = `AWS_IAM` (SigV4) or `NONE` only [L-auth] | IAM, JWT, Lambda authorizer [L-decide] |
| Bearer token | No built-in check. With `NONE`, the function itself must check the header [L-auth] | Lambda authorizer with identity source `$request.header.Authorization`; simple `isAuthorized` response; result cache up to 1 h [AG-authz-blog]. Authorizer response timeout 10 000 ms [AG-quotas] |
| Endpoint | `https://<url-id>.lambda-url.<region>.on.aws`, fixed for life, dual-stack IPv4/IPv6, public Internet only [L-urls] | `execute-api` endpoint; custom domains supported [L-decide] |
| TLS / HTTPS | URL format is HTTPS; the AWS decision page says function URLs "support both HTTP and HTTPS endpoints" [L-decide] | — (not checked further) |
| Throttling | None beyond Lambda concurrency; 429 when reserved/account concurrency is exhausted; default 1 000 concurrent executions per region [L-decide] | Account default 10 000 rps, burst 5 000; per-route throttles [L-decide] |
| Price | No charge for the URL itself; only Lambda requests + duration [L-decide] | $1.00 per million requests (first 300 M), metered in 512 KB increments [price-API, AG-pricing] |
| Free tier | Lambda always-free: 1 M requests + 400 000 GB-s per month [L-pricing] | 1 M HTTP API calls/month for the first 12 months only [AG-pricing] |

Notes:

- With `AuthType: NONE`, the function's resource-based policy must still grant public access. New function URLs created from October 2025 need both `lambda:InvokeFunctionUrl` and `lambda:InvokeFunction` in that policy [L-auth].
- The phone holds no AWS credentials (map #1), so `AWS_IAM` on a function URL would need SigV4 signing from the phone. That rules it out under the map's frame; `NONE` + in-function token check is the remaining function-URL option.
- A function URL in `RESPONSE_STREAM` mode streams via `InvokeWithResponseStream`. Native streaming is Node.js only; a Go custom runtime must implement the streaming Runtime API itself [L-stream, L-custom]. Streamed invocations keep running and billing if the client disconnects [L-stream].
- API Gateway's 30 s cap applies to the integration, so a synchronous request covering a 60–90 s handshake wait cannot succeed there. A request that returns at "public IP known" (section 1) is not covered by a documented bound.

### Cost at near-zero traffic

us-east-1 list prices [price-API]:

- Lambda requests: $0.20 per million (x86 and arm64).
- Lambda duration: x86 $0.0000166667/GB-s, **arm64 $0.0000133334/GB-s** (tier 1).
- API Gateway HTTP API: $0.000001 per request (first 300 M).

Example, not a recommendation: 100 launches/month × 30 s × 128 MB arm64 = 375 GB-s → $0.005 before the free tier, $0 within it. The same 100 requests through HTTP API cost $0.0001 (or $0 within the 12-month free tier). At this volume both are effectively free; the EC2 Exits dominate cost.

## 3. Go on Lambda (`provided.al2023`, arm64)

- Go has no managed runtime. `go1.x` is deprecated; Go functions use the OS-only runtime `provided.al2023` (or `provided.al2`), which supports arm64 (Graviton2) [L-go].
- `provided.al2023` deprecation: 30 Jun 2029; create blocked 31 Jul 2029; update blocked 31 Aug 2029 [L-go].
- AWS does **not** publish a cold-start figure for Go or for `provided.al2023`. None was measured for this note.
- The `Init` phase is limited to 10 s for on-demand functions; if exceeded, Lambda retries `Init` at first invoke under the function timeout [L-lifecycle].
- Custom runtimes were already billed for `Init`. From 1 Aug 2025 `Init` is billed for all configurations [L-init-blog].
- Lambda "might occasionally" pre-initialise environments and keeps them for an undocumented time; AWS says not to depend on this [L-lifecycle]. At near-zero traffic, most requests should be expected to be cold.
- SnapStart and provisioned concurrency lift the 10 s `Init` limit [L-lifecycle]; SnapStart was not checked for `provided.al2023` support.

## 4. One home-region Lambda calling EC2 in many regions

- EC2 is a regional service with a regional endpoint per region; an SDK client is pointed at one region [EC2-endpoints]. poof already does this: one `Provisioner` (EC2 + SSM client) per region.
- IAM roles are global. Enabling an opt-in region "propagates your IAM resources such as users and roles to the Region" [opt-in-blog].
- Regions launched before 20 March 2019 are enabled by default. Later regions are opt-in and must be enabled per account before any API call works there [opt-in-devops-blog, acct-regions]. Enabling is free; status is asynchronous (`ENABLING` → `ENABLED`) and some services may lag after `ENABLED` [acct-regions].
- Session tokens from the **global** STS endpoint are version 1 by default and "do not work in manually enabled Regions"; regional-endpoint tokens and version-2 global tokens do [STS-prefs]. How the Lambda service sources the execution role's credentials was not verified here; the relevant risk is opt-in regions only.
- Region scoping in IAM: all EC2 actions support `aws:RequestedRegion` and `ec2:Region` [EC2-policy]. EC2 quotas are per region [EC2-quota-kc].
- A Lambda not attached to a VPC reaches public AWS endpoints directly; a VPC-attached Lambda needs explicit internet access to call the EC2 API [KC-lambda-ec2].
- Regions launched after 30 Oct 2021 reject EC2 API calls over TLS 1.0/1.1 or plain HTTP [EC2-endpoints]. Current AWS SDKs use TLS 1.2+.

## 5. Does the 60–90 s wait force launch-then-poll?

Facts that bear on it, without choosing:

- **API Gateway HTTP API**: any single request is capped at 30 s, not raisable [AG-quotas]. A request covering the full 60–90 s cannot complete. A request covering only `Launch` (to public IP) depends on an undocumented EC2 latency.
- **Function URL**: a single request may run up to 900 s [L-timeout], so a synchronous call covering 60–90 s is within Lambda's limit. Lambda does not document a separate function-URL idle timeout; intermediate networks and the phone's HTTP client timeouts were not checked.
- In poof today, the handshake wait is done by the WireGuard client, not by the AWS-side code (section 1). The control plane cannot observe the handshake directly unless it polls the Exit some other way.
- Synchronous Lambda invocations have a hard 15-minute limit; asynchronous (`Event`) invocations and Lambda durable functions can run longer and suspend without compute charges [L-faq, L-durable-blog]. These are options for a launch-then-poll design; none is needed to fit inside 900 s.
